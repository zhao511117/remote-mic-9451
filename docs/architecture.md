# 协议与架构

本文只记录一个18D1:9451:0105仿Google TV遥控器的验证结果，不把它套用于小米、原版Chromecast或其它固件。

## 声音路径

当前运行路径为 `cached_link.BleakAtvvLink`。它在Bleak 2.1.1的Windows后端中使用已配对地址和缓存服务，绕过隐式扫描；不删除配对，也不扫描其它未选设备。macOS不能复用此Windows后端。

| GATT对象 | UUID |
|---|---|
| ATVV service | ab5e0001-5a21-4f05-bc7d-af01f617b664 |
| TX | ab5e0002-5a21-4f05-bc7d-af01f617b664 |
| AUDIO | ab5e0003-5a21-4f05-bc7d-af01f617b664 |
| CONTROL | ab5e0004-5a21-4f05-bc7d-af01f617b664 |

帧长134字节：2字节大端帧号、1字节保留字段、2字节大端有符号预测值、1字节步长索引，后接128字节IMA ADPCM，高半字节在前。每帧重置解码状态，8kHz单声道解码后六倍重采样到48kHz，双声道复制写入VB-CABLE。

该设备常见分片为6×20+14字节。分片损坏时先丢弃不完整帧，到14字节尾片重新找边界，避免把下一帧持续按错误偏移解码。

协商CAPS示例为 `0b0100010300860000`。当前原生开始通知为 `04 03 01 <id>`，实际释放终止为 `00 02`。测试过的简化打开/关闭命令为 `0c` / `0d`；完整协商见 `protocol.py`。

## 15秒限制

这个样本无论是否仍按住，约15秒都会终止一段流。标准MIC_EXTEND及重复MIC_OPEN未能重置其计时。当前方案在物理按住状态内每10秒关闭并重开，忽略内部切段的逻辑松键，保持右Alt一次按下；真实 `0002` 到来才提交输入法。

`hold_cycle.py` 处理关闭/重开与松手交叉的竞态、迟到开始通知以及120秒保护上限。切换间隔实测约15毫秒，但不能保证采样完全连续或绝无漏词；持续约31秒数字序列已由实物验收。

## 按键路径

三字节Consumer报告：`02 <selector> 00`，它是选择器而非位掩码。上1、下2、左3、右4、确定5、返回6、主页7、静音9、YouTube10、Netflix11、电源12、信号源13。此次未重新采集的语音键由ATVV控制链路处理，不把描述符中的其它选择器当成实按证据。

RawInput只按配置中的容器标识接收方向/确定，并在断开或退出时释放已注入键。系统还会处理部分原生Consumer用法，因此直接追加快捷键会双触发。

实验额外键模块在已校验的HID-over-GATT回调中，先匹配所选设备的蓝牙地址，再对已知两字节报告中和6/7/10/11/12/13。静音和方向报告保持原样；未知来源/格式保持原样。Python端每0.4秒续约，期限2秒。模块停止、宿主分离或续约失效后不再抑制。文件哈希、加载路径、架构和回调字节均有校验；没有向内核安装过滤驱动。

应用键使用当前前台状态决定置前或最小化。置前先走正常API；失败后短暂左Alt再试，并检查实际GetForegroundWindow。仅还原最小化窗口，不改变已最大化窗口状态。

## 生命周期

`login_start.pyw` 等待当前Windows会话的豆包服务稳定出现，启动接收器后常驻。`process_control.py`提供独立单实例和停止事件。`recovery.py`只对稳定运行60秒后消失超过3秒的组件恢复，每组件每小时最多两次；启动失败不会无限重试。显式停止会结束看护；按键模块显式禁用也会被尊重。

当前只检查进程存在性，不是完整音频健康检查。真实故障若把所有组件和看护都结束，仍需手动启动或重新登录。
